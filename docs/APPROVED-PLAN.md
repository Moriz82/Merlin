# Approved plan: Harbinger and Merlin

Approved 2026-09-08. Source: current user request in this Codex thread.

Publication update 2026-09-24: the Harbinger and Merlin source repositories are public. The private-repository line below records the original plan; engagement data, keys, and runtime state remain private.

Harbinger imports human-run tool output, maps evidenced relationships, and stores tester notes.
Merlin provides a lead queue, Markdown drafts, revision review, and approved report-specific Ghostwriter delivery.
No scanner execution, exploit execution, model transport, or AI harness integration is in scope.
Use separate private repositories, React/TypeScript interfaces, FastAPI, SQLite, and offline file fallback.
Harbinger must retain the italic reminder: report as you go.
All five tracks require tested format adapters and visible partial/unsupported states.
Keep source artifacts restricted. Require approved encrypted storage for client use.
Use contained parsers with no network; bounded uploads and atomic merges.
Use individual accounts, HTTPS on LAN, CSRF protection, immutable revisions, UTC audit, and conflict review.
Harbinger owns technical records. Merlin owns drafts. Ghostwriter owns delivered final prose.
Sign manifests and encrypt client transfers with age. Never import another SQLite database.
Uncertain Ghostwriter delivery requires reconciliation; never blindly retry a mutation.
Add a reviewed common installer and NXC configuration repair to the private toolkit.
Use Luna builders and independent review. Preserve existing projects and services.
Test all import tracks, faults, access controls, concurrent saves, LAN/file transfer, accessible UI,
backup/restore, both dedicated Kali images, and actual Ghostwriter document output.
A development checkpoint is not a competition release. Record missing evidence in READINESS.md.
